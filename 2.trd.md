7. Constraints & Technical Rules

These rules are mandatory for development.

Security
API keys must never be stored in frontend source code.
Secrets must be stored using environment variables.
GitHub access tokens must remain server-side.
All production communication must use HTTPS.
Database access must follow role-based permissions.
Code submitted by users must execute inside an isolated sandbox.
Arbitrary network access from coding sandboxes must be disabled unless specifically required.
CPU, RAM, execution time, and process limits must be enforced.
Integrity System

The system must not treat one event as automatic proof of cheating.

Instead:

Typing Activity
       +
Paste Events
       +
Tab/Window Events
       +
Code Evolution
       +
Test Execution
       +
Code Similarity
       ↓
Integrity Engine
       ↓
Evidence Report
       ↓
Normal / Review Required / Disqualified

A large paste event alone must not automatically result in disqualification.

AI Rules

AI must:

Analyze actual project evidence.
Generate questions based on the submitted project.
Reference available technical evidence.
Distinguish evidence from inference.
Provide explainable assessment signals.
Allow human review for disputed or ambiguous results.

AI scores must be treated as assessment signals, not absolute proof of technical ability.

Game Rules

The game is an engagement and progression layer.

Game XP, cosmetics, and achievements must not automatically increase professional capability scores.

Game Progress ≠ Professional Capability

Professional capability must come from verified engineering evidence.

Privacy

Screen sharing, camera, microphone, voice recording, and other monitoring features require explicit user consent.
